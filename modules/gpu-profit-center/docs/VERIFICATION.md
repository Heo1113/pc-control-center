## 1. 개발 환경에서 한 검증 (Linux 컨테이너, GPU 없음)

- .NET SDK 10.0.114 (Ubuntu 24.04 패키지). `dotnet build GpuProfitCenter.slnx`: WPF 프로젝트(XAML 컴파일 포함)까지 경고 0, 오류 0.
- `dotnet test`: 아래 자동 테스트 144개 통과.
- `gpc` 명령줄: 데모 데이터 생성, 세션 조회, CSV·JSON·기간 내보내기, 백업(같은 이름 덮어쓰기 거부, 종료 코드 1), 백업 검증, 재계산, 상태 조회를 실제로 실행해 확인.
- XAML 바인딩 경로를 C# 공개 속성 이름과 대조하는 정적 점검(스크립트): 모든 경로가 존재.

GPU·Windows GUI는 이 환경에서 실행할 수 없으므로 아래 2·3절의 Windows CI와 사용자 PC 검증으로 나눴습니다.

## 3. Windows CI (GitHub Actions `windows-latest`)

`.github/workflows/ci.yml`의 Windows 작업:

1. Release 빌드, 자동 테스트
2. `scripts/smoke-cli.ps1`: 데모 데이터, 내보내기, 백업·덮어쓰기 거부·검증, 재계산, 상태
3. `scripts/publish.ps1`: 자체 포함 단일 EXE(`GpuProfitCenter.exe`, `gpc.exe`), 포터블 zip, SHA-256
4. `scripts/smoke-gui.ps1`: 게시된 EXE로
   - **mock-demo**: MOCK 센서 + MOCK 데모 데이터
   - **real**: 러너의 실제 센서 (러너에는 NVIDIA GPU가 없으므로 "GPU 미지원" 경로)
   - **after-kill**: 세션을 기록 중인 앱을 강제 종료 → `gpc status`로 강제 종료 전 샘플 보존, 무결성 `ok`, 끝나지 않은 실행 1개, 열린 세션 1개 확인 → 같은 폴더로 다시 실행해 실행 1개·세션 1개 복구 확인
   - 각 실행은 8개 화면을 모두 열고 주요 명령(작업 생성, 기록·일시정지·재개·종료, 수익·비용, 계산 저장, 비교·내보내기, 시나리오·민감도, 기록 내보내기, 회계 조건 저장, 백업, JSON 내보내기, 무결성 검사, 글자 크기 130%)을 실행하고, 화면마다 스크린샷과 JSON 보고서를 남깁니다. 처리되지 않은 예외나 바인딩 경로 오류가 있으면 실패합니다.
5. 패키지와 스모크 증거(스크린샷, 보고서)를 아티팩트로 올립니다.

CI 결과는 4절에 적습니다.

확인된 것: 실제 NVML 경로(장치 인식, 전력·온도·사용률·VRAM·클럭·전력 제한 읽기), CPU·RAM 센서, 실시간 차트, 대시보드 빈 상태 안내, 다크 테마와 한글 표시.
이 관찰로 고친 것: 정수 단위로 바뀌는 온도(30↔31 °C)가 차트 전체 높이의 계단으로 과장되던 문제(온도 차트 최소 표시 폭 10 °C), 하드웨어 화면의 "저장된 샘플" 수가 화면을 열 때 값에 멈춰 있던 문제, 상태 표시줄 DB 크기가 WAL을 빼고 계산되던 문제.
추가 스크린샷(2026-11-06): 센서 지원 상태 표에서 GPU 누적 에너지 카운터를 포함한 NVML 지표 13개가 모두 "정상", CPU 온도·전력은 설계대로 "관리자 권한 필요"(수집 안 함). 이 화면으로 고친 것: 표·차트 위에서 마우스 휠로 페이지가 스크롤되지 않던 문제, 센서 지원 상태 표의 설명 열이 좁아 세로로 길게 늘어나던 배치.
사용자가 새 빌드에서 표·차트 위 마우스 휠 스크롤이 정상 동작함을 확인했습니다(2026-11-05).
같은 시점 비교가 아닌 NVIDIA 앱 화면(87 W, 32 %)만으로는 정확도를 판단할 수 없습니다.
아직 확인하지 않은 것: 같은 순간의 측정값 비교, 실제 GPU로 기록한 세션의 에너지·손익 계산.
