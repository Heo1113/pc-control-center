# 데이터 모델

앱 전용 SQLite 데이터베이스 `gpc.db` 하나에 모든 기록을 저장합니다(스키마 버전 1, `PRAGMA user_version`).
WAL 저널과 `synchronous=FULL`을 쓰므로, 커밋된 쓰기는 앱 강제 종료나 전원 차단 뒤에도 남습니다.
시각은 UTC Unix 밀리초, 금액은 문자열 decimal(invariant)입니다.

## 데이터 폴더

| 위치 | 조건 |
|---|---|
| `--data-dir DIR` | 지정한 폴더 |
| `실행 파일 폴더\data\` | 실행 파일 옆에 `portable.txt`가 있고 그 폴더에 쓸 수 있을 때 (포터블 패키지 기본값) |
| `%LOCALAPPDATA%\GpuProfitCenter\` | 그 밖의 경우 |

폴더 안: `gpc.db`(+ `-wal`, `-shm`), `settings.json`, `logs\gpc-YYYYMMDD.log`, `backups\`, `exports\`, `gpc.lock`(실행 중 잠금, 데이터 없음).

## 테이블

| 테이블 | 내용 | 비고 |
|---|---|---|
| `meta` | 앱 식별자, 생성 시각, **회계 조건**(JSON: 전기요금, 기본 전력 기준, 가정 W, 최대 샘플 간격 등) | 회계 조건이 데이터와 함께 백업됩니다 |
| `app_runs` | 앱 실행 단위(시작, 하트비트, 종료, 종료 이유, MOCK 여부, 샘플 간격) | 끝나지 않은 실행은 다음 시작 때 마지막 기록 시점으로 닫힘 |
| `devices` | GPU 장치(번호, 이름, MOCK 여부, VRAM, 전력 제한) | (번호, 이름, MOCK) 고유 — 다중 GPU 구분 |
| `gpu_samples` | GPU별 샘플: 전력 W, 사용률, 메모리 사용률, 온도, VRAM, 클럭, NVML 누적 에너지 mJ | 기본키 (장치, 시각) → 같은 샘플은 한 번만 저장 |
| `system_samples` | CPU 사용률, RAM 사용량 | 기본키 시각 |
| `gaps` | 기록 공백: 샘플 공백, 절전, 시각 변경, 센서 사용 불가, 앱 비정상 종료 | 에너지 보간 안 한 이유를 설명 |
| `workloads` | 작업(이름, 유형: 채굴·AI 추론·GPU 컴퓨팅·기타, 메모, 보관 여부) | 특정 코인·플랫폼에 묶이지 않음 |
| `sessions` | 세션(작업, 상태, 출처: 기록/직접 입력, MOCK 여부, 대상 GPU, 실행 확인, 수익 없음 확인, 세션별 전력 기준·가정 W·단가·전력계 kWh·작업 시간) | |
| `session_segments` | 세션 기록 구간(시작, 끝, 끝난 이유, 실행 번호) | 일시정지 = 구간 사이 |
| `revenue_entries` | 수익(종류, 금액, 통화, 수수료 전 여부, 발생 시각, 공급자, 외부 ID, 출처, 항목 환율) | (공급자, 외부 ID) 고유 → 가져오기 중복 방지 |
| `cost_entries` | 비용(범위: 세션/작업/전체, 분류, 방식, 금액 또는 비율, 통화, 적용 여부) | |
| `equipment` | 장비(가격, 잔존가치, 감가상각 방식·기간, 적용 작업) | |
| `exchange_rates` | 환율(통화, 1단위당 원화, 기준 시각, 출처) | 사용자 입력 또는 가져온 파일 |
| `session_results` | 계산 이력(계산 시각, 엔진 버전, 입력 해시, 사유, 요약 JSON, 조건 JSON) | 해시가 바뀔 때만 새 행 |
| `scenarios` | 시나리오(종류, 조건 JSON, 원본 세션과 그 해시, 저장 당시 결과) | |

## 세션 상태

`기록 중` → (`일시정지` ↔ `기록 중`) → `종료` 또는 `중단`.
기록 중에 앱이 비정상 종료되면 다음 시작 때 열린 구간을 그 실행의 마지막 하트비트·샘플 시각에 닫고 `비정상 종료 후 복구됨`으로 바꿉니다(앱이 꺼져 있던 시간은 넣지 않음). 이 세션은 재개할 수 있습니다.
앱을 정상 종료하면 기록 중인 세션은 `일시정지`가 됩니다.

## 데이터 보호

- 다른 앱의 데이터베이스나 더 새로운 버전의 데이터베이스는 열지 않습니다(파일을 바꾸지 않음).
- 손상된 데이터베이스는 삭제하지 않고 `gpc.corrupt-날짜.db`로 옮겨 보관한 뒤 새로 만듭니다.
- 백업은 SQLite 온라인 백업으로 일관된 사본을 만들고 검증합니다. 이미 있는 파일은 덮어쓰지 않습니다.
- 복원은 백업을 검증한 뒤, 현재 데이터베이스를 `gpc.before-restore-날짜.db`로 보관하고 바꿉니다. 실패하면 원래 파일을 되돌립니다.
- 보존 기간(기본 180일)이 지난 센서 샘플은 지우지만, 세션 구간 안(앞뒤 60초 포함)의 샘플은 지우지 않습니다. 세션·수익·비용·결과는 자동으로 지우지 않습니다.
- 메모·제목·공급자 이름 등 자유 입력에서 개인키(PEM, WIF, xprv), 시드 문구, API 키·비밀번호로 보이는 텍스트는 저장을 거부합니다. 지갑 주소와 거래 ID는 저장할 수 있습니다.
- 로그는 A의 `SecretRedactor`로 비밀값을 가립니다. 내보내기 파일에는 사용자 이름·컴퓨터 이름·이 PC의 경로를 넣지 않습니다(사용자가 쓴 메모는 들어갑니다).

## 설정 파일 (`settings.json`)

PC별 설정만 담습니다: 샘플 간격(초), GPU·시스템 센서 사용, 센서 기록 보존 기간, 글자 크기 배율, UTC 표시.
읽을 수 없는 설정 파일은 `settings.json.invalid-날짜`로 보관하고 기본값을 씁니다.

## 내보내기 형식

| 파일 | 내용 |
|---|---|
| 세션 CSV | 세션별 시간·에너지(출처별 비중)·관측률·전기요금·비용·종류별 수익·손익 지표, 정의되지 않은 값의 이유, 경고, 입력 해시 |
| 세션 에너지 CSV / 샘플 CSV | 에너지 구성요소, GPU별 측정, 공백, 계산 조건 / 원본 전력 샘플 |
| 수익·비용 CSV | 입력한 항목 그대로 |
| 기간 CSV | 일·주·월 합계 |
| 전체 JSON (`gpu-profit-center/ledger` v1) | 회계 조건, 작업, 세션(구간, 최신 계산 결과 전체), 수익, 비용, 장비, 환율, 시나리오, 공백 |

CSV는 UTF-8(BOM), RFC 4180이며 스프레드시트 수식 주입을 막습니다(A의 `CsvWriter`). 정의되지 않은 값은 빈 칸(JSON은 `null`과 이유)입니다.

## 외부 데이터

네트워크로 외부 API를 호출하지 않습니다. 이용 조건을 확인한 공식 API가 없기 때문입니다. 외부 데이터는 다음 경로로만 들어옵니다.

- **지급 내역 CSV 가져오기**: 사용자가 풀·마켓·클라우드 콘솔에서 내려받은 파일. 시각·금액 열이 필요하며, 통화·ID·메모·원화 환율 열은 선택입니다. 행마다 공급자, 외부 ID, 출처(외부 보고), 가져온 파일과 시각을 기록합니다. 같은 파일을 다시 가져와도 중복 저장하지 않습니다.
- **환율**: 사용자가 기준 시각·출처와 함께 입력합니다.
