# 계산 근거

모든 화면, `gpc` 명령, 자동 테스트는 같은 계산 엔진(`src/GpuProfit.Accounting`)을 씁니다. 이 엔진은 데이터베이스·시계·파일을 직접 건드리지 않는 순수 함수입니다.
계산할 수 없는 값은 0이 아니라 **N/A(정의되지 않음)** 로 표시하고, 이유를 함께 보여 줍니다.

## 1. 값의 출처 구분

모든 값과 계산 구성요소에 출처를 붙입니다.

| 출처 | 뜻 | 예 |
|---|---|---|
| 실측 (`Measured`) | 이 PC의 센서가 읽은 값 | NVML GPU 보드 전력 |
| 사용자 입력 (`UserEntered`) | 사용자가 직접 입력한 값 | 외부 전력계 kWh, 실제 수령액 |
| 외부 보고 (`ExternalReported`) | 외부 서비스가 보고한 값 | 풀 대시보드 금액, 가져온 지급 내역 CSV |
| 추정·가정 (`Estimated`) | 사용자 가정이나 추정 | 시스템 추가 전력, 유휴 전력 차감, 월 비용 시간 배분, 감가상각 |
| 계산 (`Calculated`) | 다른 값에서 정확히 계산한 값 | 시간당 비용 × 기록 시간 |

## 2. 에너지 적산 (`EnergyIntegrator`)

GPU별로 전력 샘플 `(시각 t, 전력 P)`을 실제 타임스탬프 순서로 정렬해 계산합니다(같은 시각이 중복되면 처음 값만 씀).

- 연속한 두 샘플의 간격이 **최대 샘플 간격**(기본 10초, 설정 가능) 이하이고 두 값이 모두 유효하면, 그 사이 전력이 직선으로 변했다고 보고 사다리꼴로 적분합니다.
  `E = (P₁ + P₂) / 2 × Δt`
- 간격이 최대 샘플 간격을 넘으면(앱 종료, 절전, 멈춤), 또는 한쪽 값이 없거나 비정상이면(센서 오류, GPU 연결 끊김) 그 구간은 **미관측**입니다. 에너지를 보간하지 않고 공백으로 보고합니다.
- 세션 구간(일시정지로 나뉜 구간)의 경계는 그 경계를 걸친 샘플 쌍 안에서만 선형 보간해 자릅니다. 구간 밖의 샘플은 경계를 덮는 데만 쓰입니다.
- 유효하지 않은 전력: 없음(null), NaN/무한대, 0 W 미만, 5,000 W 초과. **0 W는 유효한 측정값**입니다.
- 겹치는 구간은 합쳐서 같은 시간을 두 번 세지 않습니다.
- NVIDIA 드라이버가 누적 에너지 카운터(`nvmlDeviceGetTotalEnergyConsumption`)를 제공하면 같은 관측 구간의 카운터 증가량도 계산해 적분값과 비교합니다. 이 값은 교차 확인용이며 합산하지 않습니다. 카운터가 줄어들면(드라이버 재시작) 그 구간은 카운터 계산에서 뺍니다.
- 관측률 = 관측 시간 ÷ 세션 기록 시간. GPU가 여럿이면 가장 낮은 관측률을 세션 관측률로 씁니다.

GPU 전력 샘플이 하나도 없으면(GPU 미지원, 센서 꺼짐) GPU 에너지는 0 Wh가 아니라 **"관측 안 됨"** 이고, 총에너지와 전력비도 정의되지 않습니다. 이때는 외부 전력계 값을 입력해 계산할 수 있습니다.
기록 시간이 0인 세션의 에너지는 0 Wh로 정의됩니다.

## 3. 전력 산정 기준

| 기준 | 구성요소 |
|---|---|
| GPU 보드 전력 실측만 | GPU 실측 (CPU·메인보드·팬·전원 손실 제외 → PC 전체 전력보다 작음) |
| GPU 실측 + 시스템 추가 전력 가정 | GPU 실측 + 가정 W × 세션 기록 시간 (추정) |
| 외부 전력계 PC 전체 전력 | 사용자가 입력한 kWh만 사용. GPU 실측값은 참고로만 표시 |
| 증분 전력 | GPU 실측 − 유휴 W × GPU별 관측 시간(GPU별로 0 Wh 미만이 되지 않도록 제한) (+ 작업으로 늘어난 시스템 전력 가정) |

**미관측 구간 처리**: 기본값은 "제외"입니다. 사용자가 "관측 평균으로 추정"을 고르면 GPU별 시간 가중 평균 전력 × 미관측 시간을 **추정 구성요소로 따로** 더합니다. 실측과 섞지 않습니다.

## 4. 전기요금

- **사용자 지정 유효 단가(정확)**: `전력비 = kWh × 원/kWh`. 세션별 단가를 따로 지정할 수도 있습니다.
- **누진 단계 단순 추정**: 사용자가 단계표(상한 kWh, 단가, 기본요금)와 작업을 뺀 가구 월 사용량 H를 입력합니다.
  작업 월 사용량 가정 M(없으면 세션 사용량)에 대해 `유효 단가 = (요금(H+M) − 요금(H)) ÷ M` 이고,
  `요금(x) = (x가 속한 단계의 기본요금 + 단계별 사용량 × 단가) × 세금·기금 배율` 입니다.
  실제 고지서는 검침 기간·계절 단계·할인·절사에 따라 달라지므로 결과는 항상 **추정**으로 표시합니다. 앱은 요금표를 내장하지 않습니다.

## 5. 비용

| 방식 | 세션 배분 |
|---|---|
| 일회성 금액 (세션 범위) | 금액 그대로 |
| 일회성 금액 (작업·전체 범위) | 세션에 배분하지 않고, 발생한 기간의 기간 합계에서만 뺌 |
| 시간당 금액 | 금액 × 시간 기준 |
| 월 금액 | 금액 × 시간 기준 ÷ 730.5 시간 (추정) |
| 매출 대비 비율 | 수수료 전(gross) 매출 × 비율 |
| 장비 감가상각 (정액법) | (가격 − 잔존가치) ÷ 기간(개월) × 시간 기준 ÷ 730.5 (추정) |
| 장비 감가상각 (사용 시간) | (가격 − 잔존가치) ÷ 수명(시간) × 시간 기준 |

외화 금액은 환율로 원화로 바꿉니다. 환율이 없으면 그 금액과 그 금액이 들어가는 합계는 정의되지 않습니다.
금액은 `decimal`로 계산하고 데이터베이스에는 문자열(invariant)로 저장합니다. 부동소수점으로 저장하지 않습니다.

## 6. 수익과 손익

수익 항목 종류: **실제 수령**, **미정산·미수령**, **외부 서비스 보고**, **예상(가정)**.

| 손익 기준 | 포함하는 수익 |
|---|---|
| 실현 (확정) | 실제 수령만 |
| 미확정 포함 (확정 아님) | 실제 수령 + 미정산 + 외부 보고 |
| 예상 | 예상(가정)만 |

- 수익을 하나도 입력하지 않았으면 매출은 0원이 아니라 **"수익 미입력"** 이고 순수익도 정의되지 않습니다.
- 사용자가 "수익 없음 확인"을 체크한 세션(비용만 발생)은 매출 0원으로 정의되어 손실로 계산됩니다.
- 다른 종류의 수익만 있고 실제 수령이 없으면, 실현 매출은 0원(아직 받은 돈 없음)이며 화면에 그렇게 표시합니다.
- 외화 수익의 환율 선택 순서: 항목에 지정한 환율 → 발생 시각 이전의 가장 최근 환율 → (없으면) 이후 가장 이른 환율(경고 표시).

| 지표 | 식 | 정의되지 않는 경우 |
|---|---|---|
| 총비용 | 전력비 + 기타 비용 + 수수료 | 전력비나 비용 하나라도 계산 불가 |
| 순수익 | 매출 − 총비용 | 매출 또는 총비용 불가 |
| 시간당 순수익 | 순수익 ÷ 시간 기준 | 시간 0 |
| 에너지당 순수익 | 순수익 ÷ kWh | 0 kWh 또는 에너지 불가 |
| 수익률 | 순수익 ÷ 매출 | 매출 0 |
| 비용 대비 수익률 | 순수익 ÷ 총비용 | 총비용 0 |
| 손익분기 매출 | 수수료 외 비용 ÷ (1 − 수수료율) | 수수료율 ≥ 100% |
| 손익분기 전력 단가 | (매출 − 수수료 − 전력 외 비용) ÷ kWh | 0 kWh, 매출 불가. 음수이면 "전기가 무료여도 손실" |
| 장비 회수 기간 | 장비 가격 ÷ 시간당 (순수익 + 감가상각) | 감가상각 전 이익 ≤ 0, 장비 없음 |

**시간 기준**은 사용자가 작업 시간을 입력했으면 그 값, 아니면 세션 기록 시간(일시정지 제외)입니다. 에너지는 항상 기록 구간으로 계산합니다.

**작업 실행 여부**: 세션은 사용자가 기록을 켠 구간일 뿐이라 작업 실행을 주장하지 않습니다. 사용자가 확인을 체크하면 "사용자 확인"으로, 아니면 "실행 미확인"과 함께 GPU 사용률(기본 10%) 이상인 관측 시간 비율만 참고로 표시합니다.

## 7. 계산 조건과 재계산

각 결과에는 계산 조건(엔진 버전, 전력 기준, 최대 샘플 간격, 요금 근거, 가정 W, 사용한 환율 등)과 입력의 SHA-256 해시가 붙습니다.
세션 종료, 설정 변경, 사용자 저장 때 해시가 바뀐 경우에만 계산 이력에 새 행을 추가하므로, 과거 결과와 그 조건은 남습니다.
회계 조건을 바꾸면 모든 세션을 다시 계산할지 묻고, 재계산 결과는 이력에 새로 쌓입니다.

## 8. 시나리오와 민감도

시나리오는 입력한 조건이 유지된다고 가정한 **조건부 계산**이며 예측이 아닙니다.

- 가동 시간 = 하루 작업 시간 × 기간(일) × 가동률
- 에너지 = (GPU W + 시스템 W) × 가동 시간
- 매출 = 시간당 매출 × 가동 시간, 수수료 = 매출 × 수수료율
- 고정비 = 월 고정비 × 기간 ÷ 30.4375일, 감가상각 = (장비 − 잔존) ÷ 기간(개월) × 기간 ÷ 30.4375
- 손익분기 전력 단가 = (매출 − 수수료 − 고정비 − 감가상각) ÷ kWh

민감도는 한 조건만 바꾸고 나머지는 고정합니다. 순수익이 그 조건에 대해 선형이므로 손익분기점을 두 점으로 정확히 풀고, 세 번째 점으로 검증합니다.
조건의 자연 범위(가동률 0~100%, 하루 0~24시간, 수수료 0~100%, 나머지 0 이상) 밖이면 "손익분기점 없음"으로 표시합니다.
"세션에서 가져오기"는 세션의 실측 평균 GPU 전력, 실제(없으면 예상) 시간당 매출, 유효 단가를 씁니다. 원본 세션이 나중에 바뀌면 시나리오 화면에 표시합니다.

## 9. 기간 집계

일·주(월요일 시작)·월별 합계는 세션의 각 값을 기간별 기록 시간 비율로 나눕니다(자정을 넘긴 세션은 두 날짜에 나뉨).
에너지·비용·순수익을 정할 수 없는 세션은 합계에서 빠지며 개수를 비고에 표시합니다. 추정 비중 = 추정 kWh ÷ (실측 + 추정 + 입력 kWh).
