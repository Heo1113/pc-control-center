# Basalt 서버 제어 (로컬 AI › Basalt)

Basalt는 Strata에서 갈라진 Blackwell용 추론 엔진(v0.4.1)이고, 사용자 PC에서는 Strata 대신 씁니다. 이 화면은 사용자 PC에 설치된
Basalt(`C:\AI\basalt`)를 켜고 끄며, Basalt가 응답하는 동안 Basalt 자신의 웹 대시보드(`http://127.0.0.1:8080/`)를 보여 줍니다.
로컬 AI 모듈(A)과 따로 동작해서, 모듈 A가 꺼져 있거나 실패해도 쓸 수 있습니다.

> **실기기 확인 전입니다.** 실제 Basalt의 프로세스 구조와 API는 아직 이 저장소에서 확인하지 못했습니다(0단계 확인 스크립트 결과 대기).
> CI는 Basalt와 같은 모양의 가짜 서버(`basalt-fake.exe`)로 실제 Windows 프로세스·콘솔·포트를 시험합니다. 확인할 항목은 [VERIFICATION.md](VERIFICATION.md)의
> "실기에서 아직 확인하지 않은 것"에 있습니다.

## 화면

| 영역 | 내용 |
|---|---|
| 상태 줄 | 상태 점과 글자(꺼짐·켜는 중·실행 중·끄는 중·포트 사용 중(다른 프로그램)·남은 프로세스·문제 있음), 주소와 모드, 지금 상태의 뜻 한 줄 |
| 모드 | 품질용 / 빠른 모드. 다음에 켤 때 쓸 설정 파일이며 선택은 기억합니다. 두 모드는 같은 포트를 써서 동시에 켤 수 없습니다 |
| 버튼 | 켜기, 끄기, 브라우저에서 열기 |
| 알림 | 켜지 않은 이유, 끄지 않은 이유(예: 포트를 다른 프로그램이 씀), 시작 실패 |
| 마지막 끄기 | "정상 종료됨 · 남은 프로세스 없음 · 포트 비어 있음" 같은 결과. 펼치면 Ctrl+C를 보낸 곳, 끝낸 프로세스, 남은 프로세스, 포트 상태 |
| 본문 | Basalt가 응답하면 WebView2로 Basalt의 대시보드. 아니면 할 일 안내, 경로, 설정 열기, "Basalt 프로세스와 근거"(어떤 프로세스를 왜 Basalt로 봤는지) |

모드는 이 프로그램이 켰을 때만 압니다. 다른 곳에서 켠 Basalt는 "모드 알 수 없음 (이 프로그램이 켜지 않음)"으로 표시하고 추측하지 않습니다.
PC Control Center를 닫아도 Basalt는 계속 실행되고, 다음 실행 때 "실행 중"(모드 알 수 없음)으로 다시 보입니다.

## 어떤 프로세스를 Basalt로 보는가

Basalt는 `basalt.exe`(래퍼)가 엔진과 Python 서버를 띄우고, Python 서버가 포트에서 수신하며 엔진을 다시 띄울 수 있습니다.
그래서 판정은 **포트를 가진 프로세스**에서 시작합니다(`BasaltProcessTree.Identify`).

1. 포트(기본 8080)에서 수신 대기하는 프로세스 하나(TCP 목록, `GetExtendedTcpTable`). 여러 개거나 커널(PID 0·4)이면 정하지 않습니다.
2. 그 프로세스의 하위 프로세스(엔진 등). 부모 PID와 시작 시각으로 확인하고, 부모보다 먼저 시작한 프로세스는 PID가 재사용된 것이라 제외합니다.
3. 그 위의 `basalt*` 래퍼와 래퍼의 다른 하위 프로세스(서버 옆에서 래퍼가 띄운 엔진). 래퍼도 자식보다 먼저 시작했는지 확인합니다.
4. 이 프로그램이 Basalt를 켤 때 띄운 PowerShell 창(PID와 시작 시각으로 기억).

**Basalt로 인정하는 조건**: 트리에 이름이 `basalt`로 시작하는 실행 파일이 있거나, 이 프로그램이 띄운 창의 하위입니다. 아니면
"포트를 다른 프로그램이 쓰고 있음"으로 보고 **켜지도 끄지도 않습니다**. 이 프로그램 자신과 그 상위 프로세스(탐색기, 터미널),
콘솔 호스트(`conhost.exe`·`OpenConsole.exe`), 시작 시각을 읽을 수 없는 프로세스는 어떤 경우에도 끝내지 않습니다.

포트에서 아무것도 수신하지 않을 때는 이 프로그램이 띄운 창과 그 하위, 이름이 `basalt`로 시작하는 프로세스를 봅니다.
최근에 생겼으면 "켜는 중(이 프로그램 밖에서 켜는 중일 수 있음)", 오래됐으면 "Basalt 프로세스가 남아 있음"으로 표시하고 [끄기]로 정리할 수 있습니다.

## 켜기

1. 관리자 권한으로 실행 중이면 켜지 않습니다(Basalt가 관리자 권한을 물려받지 않도록). 이때는 일반 권한으로 다시 실행하거나 Basalt를 직접 켜세요.
2. 설치 폴더·시작 스크립트·모드의 설정 파일이 있는지 확인합니다.
3. 포트에 수신 프로세스가 있으면 켜지 않습니다: Basalt면 "이미 실행 중", 아니면 그 프로그램의 이름·PID와 함께 "다른 프로그램이 쓰고 있음".
   TCP 목록을 읽지 못하면 비어 있는지 모르므로 켜지 않습니다. 포트를 쓰지 않는 Basalt 프로세스가 남아 있어도 켜지 않습니다.
4. `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe -NoProfile -ExecutionPolicy Bypass -File "<시작 스크립트>" -Config "<설정 파일>"`을
   설치 폴더에서 **새 콘솔 창(최소화)** 으로 실행합니다. 실행 정책 `Bypass`는 이 PowerShell 프로세스 하나에만 적용되고 시스템 설정은 바꾸지 않습니다.
   창은 스크립트가 끝나면 닫힙니다(`-NoExit` 없음). 진행 상황은 그 창에서 볼 수 있습니다.
5. `/health`가 응답할 때까지 "켜는 중"(경과 초)으로 표시합니다. HTTP 502·503·504는 아직 올라오는 중으로 봅니다.
   창이 닫혔고 Basalt 프로세스가 10초 동안 없으면 "켜지 못했습니다"(스크립트·설정 오류 가능), 시작 대기(기본 900초)가 지나면 "문제 있음"으로 바꾸고, 자동으로 끄지는 않습니다.

## 끄기

사용자께서 확인하신 사실이 기준입니다: 창에서 Ctrl+C로 끄면 남는 프로세스가 없고, `basalt*`만 강제 종료하면 Python 서버가 남아 엔진을 다시 띄운 적이 있습니다.

1. **Ctrl+C**: `PcControlCenter.ConsoleSignal.exe <pid>`가 Basalt의 콘솔에 붙어 Ctrl+C를 보냅니다(창에서 Ctrl+C를 누르는 것과 같은 신호, 그 콘솔의 모든 프로세스가 받음).
   대상은 포트 소유 프로세스 → 래퍼 → 이 프로그램이 띄운 창 → 나머지 순서로, 콘솔에 붙을 수 있는 첫 프로세스입니다.
   도우미가 별도 프로세스인 이유: 다른 콘솔에 붙으면 그 프로세스 전체의 콘솔이 바뀌어, 셸 창이 Ctrl+C를 같이 받아 종료될 수 있습니다.
2. **기다림**: 정상 종료 대기(기본 30초, 설정 5~300초) 동안 0.5초마다, Basalt 프로세스가 모두 끝나고(새로 생긴 하위 프로세스 포함) 포트가 비었는지 봅니다.
   콘솔이 없어 Ctrl+C를 보낼 수 없으면 기다리지 않고 바로 3으로 갑니다.
3. **정리**(기다려도 남았을 때): 지금 포트를 가진 Basalt 트리와 처음 본 트리 중 아직 실행 중인 것을 이 순서로 끝냅니다.
   **포트 소유 프로세스(Python 서버) 먼저** — 엔진을 다시 띄우지 못하게 — 그다음 `basalt*` 래퍼(가까운 것부터), 하위 프로세스(깊은 것부터),
   마지막으로 이 프로그램이 띄운 창. 프로세스마다 열린 핸들로 **시작 시각을 다시 확인**하고 같을 때만 `TerminateProcess`를 부릅니다(PID 재사용 방지).
4. **다시 생긴 프로세스 감시**: 5초 동안(1초 동안 새것이 없고 포트가 비면 일찍 끝) 끝낸 프로세스들의 새 하위 프로세스를 찾아 끝냅니다.
5. **확인**: 처음 본 프로세스와 끝낸 프로세스가 하나라도 같은 PID·같은 시작 시각으로 남았는지, 포트에서 수신하는 프로세스가 있는지 보고 결과를 표시합니다.
   남은 것이 있으면 이유(권한 없음, 시작 시각 확인 불가 등)와 함께 "남은 프로세스 N개"로 표시하고 상태를 "남은 프로세스"로 둡니다.

## 대시보드 (WebView2)

- Basalt가 응답하고 이 화면이 보일 때만 WebView2를 만들고, Basalt가 꺼지거나 화면을 떠나면 해제합니다(msedgewebview2 프로세스와 메모리 반환).
- `http://127.0.0.1:<포트>`(루프백) 주소만 앱 안에서 엽니다. 다른 http(s) 링크는 사용자가 누른 경우에만 기본 브라우저로, 새 창 요청은 앱 안에서 열지 않습니다.
- 개발자 도구, 상태 표시줄, 자동 완성·비밀번호 저장은 끕니다. 프로필(쿠키·저장소)은 데이터 폴더의 `webview2`에 남습니다.
  Basalt 대시보드가 API 키 같은 값을 브라우저 저장소에 둔다면 그것도 이 폴더에 남습니다(이 프로그램은 읽지 않음).
- WebView2 런타임이 없으면 이유를 표시하고 [브라우저에서 열기]를 쓰게 합니다. WPF 요소는 WebView2 창 위에 그릴 수 없으므로 이 화면에는 겹치는 요소가 없습니다
  (Operator 승인 창은 별도 창이라 영향 없음).

| 품질용 설정 파일 | `basalt_config.json` | |

Basalt 폴더의 파일(스크립트·설정·모델)은 이 프로그램이 **읽지도 고치지도 않습니다**(존재만 확인하고 스크립트를 실행). 포트는 설정값을 쓰며, 설정 파일에서 읽지 않습니다
(Basalt 설정 파일의 키 이름을 확인하기 전이라 추측하지 않음).

## GPU 메모리 화면과의 연결

Basalt가 실행 중(켜는 중·끄는 중 포함)이면 하드웨어 › GPU 메모리가 Basalt 포트를 지켜보고, 위의 판정과 같은 규칙(포트 소유자, 하위, `basalt*` 래퍼와 그 하위,
시작 시각 확인)으로 측정된 프로세스를 Basalt에 연결합니다. 연결된 행과 상세에는 "Basalt" 표시가 붙고 종류는 LLM입니다. 이름이 `basalt`로 시작하는 실행 파일은
연결이 없어도 LLM으로 분류합니다. 모델 파일 헤더로 구성을 나누는 추정은 Strata와 같은 이유로 하지 않습니다(전문가 캐시 등 자체 배치 — Basalt에서는 실기기 확인 전의 추정).
로컬 AI 모듈이 같은 포트에 Strata API로 연결되어 있으면 도구 줄에는 Basalt 표시 하나만 둡니다.

## 로컬 AI 모듈 연결 (3번, 확인 스크립트 결과 뒤 확정)

모듈 A의 Strata 어댑터는 `http://127.0.0.1:8080`(기본값)의 `/v1/telemetry`(`schema_version` 1)를 주로 읽고, 없으면 `/metrics`+`/v1/status`로 대신합니다.
Basalt가 이 형식을 유지했다면 어댑터 없이 연결되고, 모듈 A 화면에는 원래대로 "Strata"와 "N/A"가 보입니다(모듈 A 화면은 바꾸지 않기로 함).
형식이 다르면 Basalt 어댑터를 추가하고, Basalt가 주지 않는 값은 Basalt 화면에서 "미지원"으로 표시합니다. 이 결정은 0단계 확인 스크립트(`basalt-probe.ps1`) 결과를 받은 뒤 합니다.
