통합 테스트가 확인하는 것:
- 공통 센서: 소비자 3개 → 장치 읽기 1회, 원래 측정 시각·문제 유지, 같은 값 중복 없음, 멈춘 허브가 소비자를 붙잡지 않음, MOCK 표시 유지, 스레드 풀이 막혀도 측정 시각 유지.
- A·B·C 동시 실행: 장치 읽기 횟수 = 허브 측정 횟수, A 프레임·B `gpu_samples`·C `sensor_samples`의 모든 시각이 허브 측정 시각, DB 분리.
- 장애 격리: 잠긴 모듈 하나만 실패하고 나머지는 기록, 실패/정지 모듈 화면은 자리표시, 재시작.
- 데이터 폴더: 기존 프로그램 폴더와 겹치면 거부(아무것도 만들지 않음), 단일 실행, 설정 손상 시 보관.
- 셸: 메뉴 8개·모든 화면이 한 번씩, 실시간 대시보드(MOCK 표시), C의 가상 이벤트 표시, B 추정치 표시.
- Operator 격리: E의 실행기가 경계를 넘어 계획 실행, E의 정책·승인이 먼저 결정, 셸이 정책을 우회해도 호스트가 보호/차단/관리자 창 거부,
  긴급 중단 잠금, UI 트리 왕복 동일, 호스트 소실 보고. 실제 별도 프로세스: 사망 시 재시작, 입력 중 긴급 중단 시 종료·잠금 유지·재개, 재시작 횟수 제한, 정상 종료.
- 통합 기록: 네 출처가 한 시간축에, 미관측 구간, 테스트 데이터 표시, 없는 DB는 만들지 않음.
- 데이터 이전: 리허설 후 원본 폴더 바이트 동일·새 파일 없음, 원래 프로그램 실행 중 거부, 새 스키마 거부, 적용 시 이전 파일 보관·모듈 재시작.
- 데이터 이전 실패 주입: 교체 후 확인 실패 → DB·WAL·SHM·설정 바이트 동일 복원, 새 DB 복사 실패 → 기존 파일 그대로, 이동 도중 중단 → 옮긴 것만 되돌리고
  원래 WAL은 지우지 않음(Windows에서는 잠긴 WAL로 실제 재현), 가져오다 생긴 설정 제거, 손상된 복사본(B의 자체 복원이 거부) → 모듈이 멈춘 채 남지 않음,
  되돌리기 불가 → 실패로 보고·모듈 미재시작·보관 파일 유지. (수정 전 코드에서는 이 시나리오가 모두 실패함을 확인)
- Operator 호스트: 확인할 수 없는 창(창이 아닌 핸들, 닫힌 창)에 대한 입력·포커스를 셸이 정책을 우회해도 호스트가 독립적으로 거부.
- GPU 메모리(하드웨어 › GPU 메모리, [GPU_MEMORY.md](GPU_MEMORY.md)):
  - 카운터 인스턴스 이름(PID·LUID) 해석, 알 수 없는 형식은 세기만 하고 추측하지 않음, 같은 프로세스·어댑터의 물리 부분 합산, 없는 카운터·빠진 인스턴스는 0이 아닌 N/A, 측정된 0은 0.
  - 리더: 꺼짐·사용 불가에 이유, 원래 측정 시각 유지, 30분 창 제한, 공급자 예외 격리·횟수 기록, 자체 스레드에서 읽고 화면을 열면 즉시·짧은 간격, 정상 종료, 재사용된 PID는 다른 프로세스로 기록.
  - Strata 연결: 포트 소유자 → 하위 엔진 프로세스(시작 시각 확인), 재사용된 부모 PID는 오래된 프로세스를 입양하지 않음, 시작 시각을 모르면 연결하지 않음, 원격·여러 소유자·커널 소유 포트·측정 뒤 바뀐 프로세스는 연결하지 않음.
  - 화면: 장치 막대는 종류별 측정 합계와 "나뉘지 않음"(계산)으로 나뉘고 막대가 어댑터 사용량을 넘지 않음, 합이 더 크면 경고, NVML 비교는 NVIDIA 1장일 때만, 대체 카운터 경고, **오래된 값은 현재 값처럼 표시하지 않음**, Strata 미연결·오래된 조회에서는 연결하지 않음.
  - 표·상세(2차): 가장 큰 프로세스 자동 선택, 종류·근거·런타임·안에 든 것, 접근 거부는 "권한 없음", 새 측정에도 행·선택·장치 줄 요소가 그대로(제자리 갱신), 이름·PID 찾기와 작은 프로세스, 일시정지, 화면을 볼 때만 세부 정보 요청.
  - 사용감(3차): 범례로 종류 필터(같은 종류로 해제, 활성 표시, 빈 결과 문구), 찾기는 종류·런타임·찾은 내용까지(일반 설명은 제외), 재시작한 프로세스는 같은 이름으로 따라가고 사라진 프로세스는 다른 행으로 바꾸지 않음, 행·상세 복사 텍스트(탭 구분, 추정·출처 표시), 여유 메모리·짧은 어댑터 이름, Strata 표시로 Strata 프로세스 선택(필터에 가려져도), 정렬·숨긴 열·상세 높이·작은 프로세스 기억(바뀐 것만 저장, 저장 실패 무시), 셸 설정의 `GpuMemoryPage` 왕복·예전 파일 기본값·잘못된 값 정리.
  - 추정 정정(4차): Strata에 연결된 프로세스와 MoE 모델은 헤더 기준 구성을 그리지 않고 이유를 표시, 하이브리드(SSM 등)·잠재 주의(MLA) 모델은 토큰당 KV를 계산하지 않음, 런타임이 컨텍스트를 주지 않으면 KV를 나누지 않음. 이 조건을 일부러 끄면(Strata·MoE·MLA) 해당 테스트가 실패함을 확인.
  - 추정(2차): 모든 구성 막대·범례가 "추정", KV가 남은 양에 안 들어가면 나누지 않음, 컨텍스트를 모르면 KV를 나누지 않음, Qwen3-0.6B 구조 8,192 토큰 = KV 896 MiB.
  - 엔진(2차): 인스턴스 이름(엔진 번호·종류), 프로세스 값 = 가장 바쁜 엔진(합이 아님), 어댑터 엔진 = 프로세스 합(100 상한), NaN·음수는 0.
  - GGUF(2차): v1~v3 헤더, 묶인 임베딩, 임베딩·재순위·비전 프로젝터·LoRA·비인과 모델 구분, 층별 KV 헤드·슬라이딩 윈도, **파일을 어느 길이에서 잘라도 예외 없음**, 엉뚱한 버전·거대한 개수·문자열·알 수 없는 형식·10만 단계 중첩 배열·곱셈 넘침·파일 끝 너머 오프셋, 캐시와 파일 변경.
  - 프로세스 검사(2차): 상위 25개 + 바쁜 프로세스(커널·종료·재사용 PID 제외), 5초·변화량·2분 재검사, PID 재사용 시 새로 검사, 거부된 프로세스는 2분마다만, 예산 0이면 검사 안 함, 모델 파일은 이름만(경로의 사용자 이름 없음)·LLM 먼저·최대 8개, DLL 이름 감지와 비슷한 이름 무시, 모델 파일 크기·매직 규칙.
  - 셸: 리더가 고장 나도 공통 센서·모듈은 정상, 하드웨어 메뉴의 "공통 센서" 다음 탭, MOCK 센서에서는 MOCK 공급자만 사용, 설정으로 끄기·예전 설정 파일은 켜짐.
  - Windows 전용(러너에서 실제 API): 카운터를 읽거나 이유를 말함, DXGI 어댑터·LUID, 자기 프로세스 시작 시각이 .NET 값과 1 ms 안에서 같음·측정 전 시작 판정, IPv4/IPv6 루프백 수신 포트와 소유자(바이트 순서), 실제 자식 프로세스(ping.exe)를 부모 PID·시작 시각으로 연결,
    (2차) 자기 프로세스의 DLL을 드라이브 문자 경로로 나열·System(PID 4)은 거부, **실제로 메모리 매핑한 GGUF 파일을 찾아 헤더를 읽음**, 엔진 카운터와 세부 정보는 요청할 때만.
  - 변형 확인: PID 재사용 검사와 신선도 검사를 일부러 끄면 해당 테스트가 실패함을 확인.
    (2차) 엔진 합산, 안 맞는 KV 유지, 커널·종료 프로세스가 검사 자리 차지, 빈 식별 툴팁, 텐서 오프셋 미제한을 각각 일부러 넣으면 해당 테스트가 실패함을 확인.
    (3차) 재시작 미추적, 일반 설명 검색, 종류 필터 무시, 같은 정렬 재저장, 잘못된 숨김 열 유지를 각각 일부러 넣으면 해당 테스트가 실패함을 확인.

GUI 스모크(`scripts/smoke-gui.ps1`, 게시된 `PcControlCenter.exe`):
1. mock: MOCK 센서·B/C 데모 데이터·E MOCK 데스크톱·MOCK 모델 — 모든 메뉴·화면 스크린샷, A 세션, B 세션, C 수집, Operator 자연어 작업, 승인 거부(실행 안 됨), 긴급 중단·재개.
2. real: 러너의 실제 센서(GPU 없음 → GPU 값 N/A여야 함), 실제 이벤트 로그, **실제 데스크톱에서 E의 내장 워크플로를 별도 호스트 프로세스로 실행**(테스트 앱), 데이터 이전 리허설·적용,

## 알려진 차이와 제한

- C의 알림 영역 아이콘·풍선 알림은 옮기지 않았습니다. 새 알림은 시스템 진단 화면 위 상태 줄에 표시됩니다.
- 테마: B·C·E 화면에서 A의 테마와 같은 이름의 스타일은 A(셸) 쪽 값이 쓰입니다. 큰 숫자 글자 크기가 B·C 원본의 24 대신 28, E의 카드 제목 아래 여백 4px 없음, E의 도구 단추 안쪽 여백 1px 차이(모두 모양만 다름).
- B 화면에서 공백 문자만 있는 안내 문구는 표시되지 않습니다(원본 B는 표시). 나머지 표시/숨김 규칙은 각 원본과 같습니다.
- UAC를 끈 PC에서는 관리자 계정의 프로그램이 모두 높은 무결성으로 실행됩니다. 이때 Operator 호스트는 일반 사용자 토큰(보통 무결성)으로 실행되므로,
  E의 규칙(자기보다 높은 무결성의 창은 조작하지 않음)에 따라 호스트가 직접 실행한 프로그램의 창만 조작합니다. UAC가 켜진 기본 설정에서는 원래 E와 같습니다.
- 글자 배율: 공통 설정 값이 기준입니다. B·E 설정 화면의 배율 변경은 창 전체에 즉시 적용되지만 다음 시작 때는 공통 설정 값을 씁니다.
- 각 모듈의 명령줄 도구(`lapc`·`gpc`·`wdl`·`wao`)는 패키지에 넣지 않았습니다. 이 도구들은 기본으로 **기존 프로그램의 폴더**를 쓰므로, 통합 앱 데이터에 쓰려면 `--data-dir <통합 데이터>\modules\<모듈>`을 지정해야 합니다.
- 패키지에 단일 파일 EXE가 3개(통합 창, Operator 호스트, E의 테스트 앱)라 크기가 큽니다(각각 .NET 런타임 포함).
- C의 테스트 하나(`Event_6008_localized_time_is_parsed_only_when_plausible`)가 Ubuntu 26.04(새 ICU)에서 실패합니다. Windows와 Ubuntu 24.04에서는 통과합니다.
  한국어 Windows의 6008 이벤트 시각 해석이 ICU 버전에 따라 달라질 수 있다는 뜻이므로, 새 ICU를 쓰는 Windows 버전에서 같은 일이 생기는지 원본 C에서 확인할 필요가 있습니다(통합 작업에서 C의 해석 로직은 바꾸지 않았습니다).
